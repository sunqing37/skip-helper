# 性能检查记录

2026-10-29，范围：当前代码的静态检查与最小编译；未操作手机，未采集 Perfetto、CPU、帧率、耗电或堆快照。以下是代码层面的开销及处理，不是测量后的性能保证。

| 位置 | 发现 | 处理 |
| --- | --- | --- |
| `SkipAccessibilityService` | 每个无障碍事件都读取窗口；完整树最多 600 节点在主线程反复遍历，Binder 往返可能卡住事件处理 | 合并窗口探测至最多 4 次/秒；关闭/未授权时早返回；完整扫描及执行前复核移至串行 IO，返回后校验 window generation/session |
| `OcrReader.capture` | 主线程回调复制完整截图；1080×2340 ARGB_8888 单帧约 9.64 MiB，可能造成主线程停顿 | 截图转换移到 Default executor；保留单帧任务上限、1 秒节流与位图生命周期保护 |
| `MainActivity / AppIcon` | 应用列表初始化加载所有图标，内存随安装数量增加 | 只加载可见图标，96×96、96 项 LRU，最多两个后台加载任务；缓存图像像素容量约 3.38 MiB（不含可见项引用/对象/源 drawable） |
| `Matcher` | 高频创建正则与广告标签集合 | 改为复用不可变正则和集合，不放宽匹配条件 |
| `ui/Pages / Overview` | 每次重组重新筛选排序、逐条创建日期格式器；反复线性查应用名 | 用输入作 remember key，分组共用格式器，行时间缓存，应用名预建 Map |

## 尚需人工验证

- 真机快速切换应用、撤权或锁屏时，异步快照不得点击旧页面；暂停窗口恢复后仍遵守原 15 秒期限。
- 大量无障碍事件、复杂控件树和图片广告下观察 UI 响应与识别延迟；不能因 IO 排队导致错过短倒计时。
- 滚动长应用列表、旋转屏幕、深色/大字体，以及应用卸载后的图标占位表现。
- OCR 仍保留全分辨率内存截图与中文/拉丁双识别器，避免未经实测缩图降低小字识别率；高分辨率设备可能仍有内存/CPU 峰值。
- 前台元数据读取、事件 source 读取和最终节点点击仍有少量主线程 Binder；若真机确认卡顿，应进一步基于 trace 优化，不能直接取消安全复核。
- App 列表名称查询在 IO 上，但 Activity 重建后仍会重新查询；不为静态风险提前引入全量架构重构。

没有自动化测试或性能基准。用户如明确授权性能采样，再按真实设备/版本/前后台场景采集，不用静态推断代替数字。
